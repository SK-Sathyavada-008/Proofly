# Proofly — Firebase Security Rules & Tenant Isolation Matrix (Phase 02)

**Files:** `firestore.rules`, `storage.rules`, `firebase.json`  
**Emulator Test Suite:** `tests/rules/firebaseSecurityRules.test.ts` (`npm run test:rules`)  
**Default Policy:** Explicit **Default Deny-All** (`match /{document=**} { allow read, write: if false; }` and `match /{allPaths=**} { allow read, write: if false; }`).  
**Trust Boundary:** Zero reliance on custom client claims or browser-supplied role fields. Platform Admin membership is verified exclusively via backend-managed `/platformAdmins/{uid}` (`allow read, write: if false`). Every tenant-owned resource validates authoritative organization & competition binding (`getCompetition(compId).organizationId == orgId`) and live membership documents.

## 2. Firebase Storage Security Matrix (`storage.rules`)

| Storage Path | Create (Upload) | Read (Download) | Update / Delete | Validation Rules |
|---|---|---|---|---|
| `/organizations/{orgId}/competitions/{competitionId}/submissions/{submissionId}/{fileName}` | Comp Admin/Org Admin, Authenticated Participant Owner (`submission.participantUid == auth.uid`), OR Anonymous Participant presenting valid non-revoked, non-expired `/participantSessions/{sessionId}` in custom metadata (`metadata.sessionId`) | Org Member, Comp Admin/Organizer/Viewer of `orgId`/`competitionId`, Authenticated Participant Owner, OR **Assigned Judge ONLY** when `submission.status in ['Ready for Judge Review', 'Under Human Review', 'Evaluated', 'Finalized']` | **Denied** (`false`) | Competition must exist, belong to `orgId`, and have `status == 'ACTIVE'`. Submission must exist, belong to `orgId`/`competitionId`, have `isLocked == false` and `status in ['Draft', 'Submitted']`. File size `> 0` and `<= 25 MB`. Whitelisted MIME types only (PDF, PPT, PPTX, TXT, MD, JSON, ZIP, PNG, JPEG, WEBP). Safe filename (<= 180 chars, no `..`, blocks `.exe`, `.bat`, `.sh`, `.js`, `.html`, `.php`, `.svg`, etc.). |
| `/{allPaths=**}` | **Denied** | **Denied** | **Denied** | Fail-closed default (blocks legacy `/competitions/...` and arbitrary paths). |

## 3. Known Limitations & Backend Prerequisites (Addressed in Next Phases)

1. **Client Services Pending Backend Cloud Functions Migration (Phase 03–05):**
   - Because `firestore.rules` and `storage.rules` now strictly enforce backend-only writes for `aiEvaluationReports`, `evaluationJobs`, `scoreContributions`, `scoringLedger`, `leaderboardSnapshots`, `resultPublications`, `auditLogs`, `governanceAuditLogs`, and `participantSessions`, client-side mutations to those collections will rightly be rejected by Firestore in production until Firebase Cloud Functions v2 endpoints are deployed.
   - `fileStorageService.ts` must be updated (Phase 04) to upload to the canonical tenant-scoped path `/organizations/{orgId}/competitions/{competitionId}/submissions/{submissionId}/{fileName}` with `{ customMetadata: { sessionId } }` rather than using local `Blob` URLs.
   - `judgeAssignmentService.ts` must use deterministic assignment document IDs `{submissionId}_{judgeId}` when persisted to Firestore (Phase 05) to match the O(1) rule lookup.
   - `formBuilderService.ts` should maintain sanitized public projection documents (`isPublicProjection: true, containsInternalFields: false`) separately from internal schemas containing organizer-only or judge-only fields.
2. **Firestore Rule Evaluation Costs:**
   - Cross-service `firestore.get()` calls in `storage.rules` count toward Firestore read quotas and security rule `get()` call limits (maximum 10 per request; current rules stay well under limit at 3–5 calls).
3. **Do Not Deploy Yet Without Backend Migration & Storage Setup:**
   - Rules were **NOT** automatically deployed to production (per Phase 02 restriction). Deploy manually only after verifying Blaze/Storage setup and aligning backend Cloud Functions:
     ```bash
     firebase deploy --only firestore:rules,firestore:indexes
     firebase deploy --only storage
     ```
